# Перекличка

Локальный прототип учёта посещаемости: Android работает как камера и экран,
ноутбук распознаёт лица и сохраняет отметки в SQLite. Телефон и ноутбук находятся
в одной Wi-Fi сети. Проверка живости **отключена** по текущему решению: фотография
или видео лица могут пройти распознавание.

## Запуск

Требуется Python 3.11–3.14 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --cache-dir /tmp/face-id-uv-cache
uv run --cache-dir /tmp/face-id-uv-cache python scripts/download_models.py
uv run --cache-dir /tmp/face-id-uv-cache python scripts/run_site.py
```

Панель администратора: **http://localhost:8000/admin**.
Процесс работает до Ctrl+C. HTTP: 8000, HTTPS: 8443.
Порты можно изменить флагами `--http-port` и `--https-port`.
Если выбрана виртуальная сеть, укажите адрес Wi-Fi:

```bash
FACE_HOST=192.168.1.20 uv run --cache-dir /tmp/face-id-uv-cache python scripts/run_site.py
```

При перезапуске данные сохраняются. Не запускайте несколько экземпляров с одной
папкой данных: состояние обработки кадров находится в одном процессе.

## Подключение телефона

1. Открыть панель на ноутбуке и нажать **Подключить телефон**.
2. Телефон и ноутбук должны быть в одной сети, доступ к портам 8000 и 8443 открыт.
3. Первым QR-кодом открыть инструкцию и скачать локальный сертификат CA.
4. Установить сертификат в настройках Android: Безопасность → Шифрование
   и учётные данные → Установить сертификат → Сертификат CA. Пункты зависят от телефона.
5. Вторым QR-кодом открыть терминал, разрешить камеру и нажать **Включить камеру**.

Камера браузера требует защищённого контекста. Сервер создаёт собственный CA
и HTTPS-сертификат с IP-адресами ноутбука. Ключ CA остаётся в `data/tls`;
приложение не меняет системные настройки доверия. Устанавливайте только сертификат
со своего ноутбука и удалите его из Android после эксперимента. Если адрес
ноутбука сменился, перезапустите сервер и откройте новый QR-код.

Без телефона можно попробовать **камеру ноутбука**: соответствующая кнопка
есть в окне подключения. На `localhost` браузер разрешает камеру по HTTP.

## Как пользоваться

1. На вкладке **Группы → Создать группу** добавьте нужные группы.
   Можно создавать пустые группы заранее. В списке группы нажмите **Открыть список**,
   затем **Добавить человека** — группа будет выбрана автоматически.
2. В панели **Добавить человека**: имя и группа. Терминал снимет 6 качественных
   кадров одного лица. Пока регистрация не завершилась, человек не добавляется.
3. **Начать проверку**: название и **одна или несколько групп галочками**.
   Например, ИС-201 и ИС-202 проверяются одновременно через одну камеру.
   Список участников и их группы фиксируются в этот момент. Пустые группы
   станут доступны для выбора после добавления людей.
4. Люди подходят по одному. Для отметки нужны три последовательных распознавания
   одного человека в серии длительностью не менее 0.6 секунды. Усреднённое
   представление серии проверяется повторно по всей базе. Лицо другого человека,
   отсутствие лица, несколько лиц, плохой кадр или пауза сбрасывают подтверждение.
5. Отметка сохраняется сразу, повторный подход не создаёт дублей.
   Отметить человека или снять отметку вручную можно в панели во время проверки.
6. **Завершить проверку**. До завершения статус — «Ещё не отмечен»,
   после — «Отсутствует». Итоги показываются суммарно и по каждой группе.
   Фильтр над списком позволяет открыть одну группу; CSV скачивается для всех
   участников либо для выбранной группы. История хранит состав каждой проверки.

Кнопкой **Группа** в списке людей можно перевести человека в другую группу.
Изменение применяется к новым проверкам. Даже если перевести человека во время
общей проверки двух групп, текущие отметки и сохранённая принадлежность к группе
останутся прежними. Каждая запись человека принадлежит одной группе.

Одновременно открыта одна общая проверка, в которую можно включить несколько
групп. Выбор групп не сужает базу сравнения лиц: похожий человек из другой группы
по-прежнему учитывается при проверке неоднозначности.

Регистрация во время проверки временно переключает терминал на съёмку нового
человека. Добавленный человек участвует со следующей проверки. Архивирование
убирает человека из будущих проверок; результаты прошлых сохраняются.

## Модели и точность

Основная модель — **InsightFace ArcFace `w600k_r50` (ResNet50@WebFace600K)**,
512 чисел на лицо. YuNet находит лицо, затем оно выравнивается по пяти точкам
к 112×112. Регистрация и распознавание используют одну обработку RGB
`(pixel - 127.5) / 127.5` и L2-нормализацию результата. Веса проверяются по SHA-256.
SFace (128 чисел) сохранена как отдельный вариант для отката.

Сравнение использует среднее трёх лучших шаблонов человека вместо максимума
одного случайно похожего кадра. Начальные настройки ArcFace: не менее двух шаблонов
с cosine similarity от 0.47, средний score от 0.52, сходство со средним профилем от 0.47 и отрыв
от следующего **человека** не менее 0.10. Конкуренты сравниваются по всей базе,
включая людей других групп. Неоднозначное совпадение не ставит отметку.

Модель выбирается в `data/vision.json`: `{"recognizer":"arcface"}` или
`{"recognizer":"sface"}`. Пороги хранятся отдельно по ID модели:
`data/recognition-arcface-w600k-r50-4c06341c33c2-v1.json` и
`data/recognition-sface-2021dec-v1.json`. Старый `data/recognition.json` при первом
запуске SFace используется только для сохранения её прежних настроек.
Изменения применяются после перезапуска сервера. Это стартовые настройки,
а не измеренная точность на группе из 50–70 человек. Повышение порога может
уменьшить ложные совпадения и увеличить отказы своим. Без отдельной проверки
на реальных людях нельзя обещать отсутствие ошибок.

При регистрации все шесть кадров должны согласоваться друг с другом.
Слишком похожая существующая запись блокирует добавление под другим именем.
На вкладке **Люди → Проверить похожие лица** можно найти похожие профили,
несогласованные или неполные регистрации. **Переснять** заменяет данные лица
только после успешной съёмки: имя, ID, группа и история сохраняются. Отмена
повторной съёмки оставляет старые шаблоны. Эта проверка базы не заменяет тест
на новых съёмках. Нельзя считать искусственные векторы 70 профилей тестом
точности распознавания 70 реальных людей.

Нельзя смешивать шаблоны SFace с ArcFace или переносить между ними пороги.
После перехода на ArcFace в панели появится подсказка **Нужно переснять** у людей,
зарегистрированных только для SFace. Нажмите **Переснять** и снимите шесть кадров:
имя, группа, ID и история остаются прежними. Старые шаблоны SFace не удаляются;
при повторной съёмке заменяются только данные выбранной модели. Автоматического
преобразования 128 чисел SFace в 512 чисел ArcFace нет.

Для временного отката остановите сервер и запустите:

```bash
FACE_RECOGNIZER=sface uv run --cache-dir /tmp/face-id-uv-cache python scripts/run_site.py
```

Это переопределение действует на текущий запуск, не переписывая `data/vision.json`.
SFace сможет использовать сохранённые старые шаблоны. Людей, снятых только для
ArcFace, для SFace понадобится снять отдельно.

За основу сценария взят
[Pi-Face-Recognition-Access-Control](https://github.com/Anyoz1/Pi-Face-Recognition-Access-Control),
commit `d977a19466e037ac5c76e5bc6bf860d5ae9c4acf`.
Веса ArcFace найдены в локальном проекте Orange Pi; их SHA-256 сверена с файлами
на самой Orange Pi 5B и опубликованной контрольной суммой `w600k_r50`.
Эта версия использует другой формат базы и не импортирует старые `.bin` автоматически.
Источники моделей и условия использования: [models/README.md](models/README.md).

## Проверка точности на своей группе

После регистрации все 50–70 человек ещё раз подходят к тому же телефону.
Проверяют совпадение имени и отметки; отдельно пробуют люди вне списка.
Проблемные регистрации переснимают. Если человек носит очки, стоит проверить
обычные для него варианты внешнего вида и освещения. Неотмеченного человека
можно отметить вручную, предварительно проверив его имя.

Для воспроизводимого измерения есть отдельный инструмент. Набор хранится
локально, **проверочные кадры снимаются отдельно от регистрации**:

```text
my-test/
  enrollment/
    person-001/       # ровно 6 разных кадров
    person-002/
  probes/
    person-001/       # новые съёмки этого человека
    person-002/
    _unknown/        # люди вне списка, можно с подпапками
```

```bash
uv run --cache-dir /tmp/face-id-uv-cache python scripts/evaluate_recognition.py \
  --dataset /path/to/my-test --report data/evaluation.json --sweep
```

Отчёт считает отдельно неверное имя, отказ своему и пропуск постороннего.
Непригодные кадры учитываются в результатах, отсутствующий набор посторонних
даёт `null` для их частоты ложного принятия. Точные повторы кадров и попадание
регистрационного кадра в проверку запрещены. `--sweep` сравнивает варианты
порогов, не меняя настройки сервера и рабочую базу. После выбора порогов нужен
ещё один независимый проверочный набор. Этот инструмент оценивает отдельные
кадры; временное подтверждение и весь пользовательский сценарий проверяют
живым проходом к терминалу.

## Данные и доступ

`data/attendance.sqlite3` — люди, шаблоны, проверки и аудит ручных исправлений.
Фотографии и видеозапись не сохраняются. Шаблоны являются биометрическими данными;
папки `data/` и веса моделей исключены из Git. База не шифруется приложением;
используйте защиту диска ноутбука. Копировать резервную копию SQLite следует
после остановки сервера или через SQLite backup API.

Админка первоначально открывается только через localhost на ноутбуке; по QR-коду
телефон получает отдельный доступ терминала без управления базой и отчётами.
На LAN камера передаёт кадры по HTTPS. Ссылка терминала содержит ключ подключения:
не публикуйте её. Чтобы отозвать все подключения, остановите сервер, удалите
**только** `data/tokens.json` и перезапустите его; база и сертификаты сохранятся.

Прототип рассчитан на одну камеру и один процесс сервера. Orange Pi и реальные
показатели распознавания/скорости пока не проверены.

## Проверки

```bash
uv run --cache-dir /tmp/face-id-uv-cache pytest -q
node --check static/admin.js
node --check static/terminal.js
```

Тесты проверяют регистрацию через поток кадров, подтверждение по времени, сброс
при смене человека и сессии, защиту API, отсутствие дублей, ручные отметки,
фиксацию состава группы, историю и CSV. Отдельные тесты на синтетических базах
из 50 и 70 профилей проверяют решение при похожих людях, единичном ошибочном
шаблоне и неизвестном профиле; это не оценка биометрической точности.
Тест с реальными моделями использует
локальные тестовые изображения, если они переданы через `FACE_TEST_IMAGE`
и `FACE_TEST_OTHER_IMAGE`; по умолчанию пропускается.
Также можно передать `pytest -q tests --face-test-image=/path/one.jpg --face-test-other-image=/path/two.jpg`.

При наличии весов проверяются обе модели: SFace и ArcFace. Тесты перехода между
моделями проверяют изоляцию порогов и шаблонов, отмену пересъёмки, сохранение
старой базы и истории, а также отметку после успешной пересъёмки.

Тесты нескольких групп проверяют создание пустых групп, общую проверку двух
групп, раздельные итоги, фильтр CSV, отказ человеку из невыбранной группы,
перевод между группами и миграцию старой базы с сохранением исторических списков.
